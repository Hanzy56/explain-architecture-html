# 業務から技術説明を組み立てる

## 根拠

プロジェクト固有の指示と対象資料から実態を取り出す。過去のプロジェクトのサービス名、状態、決済方式、DB境界を持ち込まない。担当者の操作を、受け付ける画面・API、処理するruntime、保存先、外部連携まで追う。呼び出す側と実行する側、同じアプリ内の処理と別serviceを分けて表す。

重要な分岐は正常系の呼び出しだけで判断せず、状態の更新箇所と条件を読む。予約状態と支払い状態のように別々に進む軸があれば、並行することを図か図の直近で示す。「APIが応答した」「外部処理が成功した」「利用者の業務が完了した」を混同しない。未確認の事項は、それが影響する説明の近くに短く残す。

GitHub等のリンクには対象プロジェクト自身のrevisionと実在するパスを使う。working treeとrevisionの内容が異なる場合は、説明対象を明示し、変更中の内容をコミット済みの根拠で証明したことにしない。originに資格情報が含まれる場合は、記録とリンクから除く。

Git identityのないプロジェクトでも、確認したローカル資料で説明できる。その場合はArchifyのrepository fieldsとGit-backedの `sources` を省き、本文にローカルパス・必要な行範囲を載せ、検証記録へ読んだファイルのSHA256を残す。図のソース検証が成功したことにはしない。配布先がソースにアクセスできなければ、閲覧可能な根拠の抜粋や同梱範囲を明示する。

## 本文の組み立て

「誰が、何をして、どの条件で次へ進むか」を業務フローにする。次の形を叩き台に、必要な段階だけを採用する。

- 業務または利用者の作業の流れ：開始、担当、判断、完了。
- 全体構成：その流れを受け持つ画面・処理・保存先。
- 各段階の技術説明：同期処理にはsequence、分岐や非同期処理にはflow。
- 共通の境界：権限、データ分離、整合性など、複数の段階に関わる仕組み。

各段階に、説明ページの対応するセクションへのリンクを置く。自動割当のパネルIDを確認してからリンクを書く。段階が多くても一律に6セクションへ押し込めない。

説明ページのMarkdownは `template: doc`、`theme: shadcn`、依頼に合った `lang` を基本にする。任意のfrontmatterは画面に表示されるため、ツール名や内部の検証情報をメタデータとして追加しない。冒頭の2文は空行で分ける。

簡略図の本文は、その図の登場人物が何をするかを説明する。Auth0や特定DBなどを使うかどうかは対象プロジェクトの根拠で決める。詳細図には要素の役割と業務との対応を載せる。コードのディレクトリ案内は、それを求められた場合だけ追加する。

## 詳細図の入力

Archifyの取得済みcheckout内の `archify/SKILL.md`、`references/authoring-defaults.md`、`references/repository-authoring.md` と、対象modeのschema/exampleを読んで候補を作る。exampleはJSONの形と配置の参考であり、プロジェクトの事実には使わない。

`candidate.json` は通常のArchify仕様。構成図には `components` と `connections` を使う。Git-backedの構成要素には `sources` を付け、接続の根拠は関連する構成要素の `sources` と本文・cardで対応付ける。Architectureの `connections` へ未定義の `sources` フィールドを追加しない。最初は自動routingを使い、ブラウザで読めない交差・ラベル・迂回が見つかった範囲だけ調整する。

`module-guide.json` は、構成要素のIDをキーにした責務と業務の対応。図に登場する各構成要素を網羅する。

```json
{
  "module-id": {
    "role": "この要素が何を受け取り、何を処理し、何を保存または送信するか。",
    "business": "関連する業務の段階"
  }
}
```

`presentation.json` は本文と詳細図の導線に共通する表示設定。文言は対象の内容に合わせる。

```json
{
  "diagramHref": "architecture.html",
  "backHref": "index.html#panel-B",
  "linkTitle": "詳細な構成図とモジュールの役割を開く",
  "linkKicker": "システム全体を詳しく見る",
  "linkDescription": "業務を支えるモジュールと、その接続を探索できます。"
}
```

同梱viewer調整は日本語の表示preset。英語などでの説明を依頼された場合は、作業用スクリプトのUI文言とフォントをその依頼に合わせる。個人用スキル自体の変更を通常の成果物作成に混ぜない。
